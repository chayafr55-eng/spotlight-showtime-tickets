# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Original brief (README): login, signup, event edit, payment accepting 2–3 listed test card numbers, order confirmation, account area, event list, with emphasis on a very modern design. All of these exist as routes.

"Tixa" — a Hebrew (RTL) event/movie ticket-booking demo site built with Lovable on TanStack Start (React 19, Vite, Tailwind v4, shadcn/Radix UI in `src/components/ui`). All UI copy is Hebrew. The project is synced with Lovable: never rewrite published git history (no force-push, rebase, amend or squash of pushed commits), and keep `main` in a working state since pushes sync back to the Lovable editor.

## Commands

Package manager is bun (`bun.lock`; `package-lock.json` is gitignored), though npm scripts work too.

- `npm run dev` — dev server
- `npm run build` — production build (nitro, Cloudflare target by default)
- `npm run lint` / `npm run format` — ESLint / Prettier
- `npm test` — vitest (jsdom) run once; `npm run test:watch` for watch mode
- Single test: `npx vitest run src/lib/payment.test.ts` (add `-t "name"` to filter)
- Tests live next to their code (`src/lib/payment.test.ts`) or in `src/test/` (`setup.ts` is the vitest setup file; `app-routing.test.tsx` is a routing integration test). `globals: true`, so `describe`/`it`/`expect` need no import.

## Architecture

- **Routing**: file-based in `src/routes/` (`events.$id.tsx`, `checkout.$id.tsx`, `confirmation.$bookingId.tsx`, `edit.$id.tsx`, `account.tsx`, `login.tsx`, `signup.tsx`, `index.tsx`). `src/routeTree.gen.ts` is auto-generated by the router plugin — don't hand-edit it. `__root.tsx` is the only layout. Don't create Next/Remix-style `pages/` or `app/` dirs.
- **Build config**: `vite.config.ts` uses `@lovable.dev/vite-tanstack-config`, which already bundles the TanStack Start, React, Tailwind, tsconfig-paths and nitro plugins plus the `@` alias — don't add them again. The SSR entry is redirected to `src/server.ts` (error-wrapping). `vitest.config.ts` is separate and sets its own `@` alias.
- **No backend — all state is client-side** in `src/lib/store.ts`: a module-level store (events, users, session, bookings) persisted to `localStorage` under `tixa-state-v1`, exposed via `useStore(selector)` (`useSyncExternalStore`) and a mutating `actions` object (signup/login/logout/saveEvent/book). SSR renders from the `seed` state; real state is loaded lazily on the client. Passwords are stored in plaintext (demo only). A permanent `GUEST_USER` is re-injected on every load and shown on the login screen.
- **Payments are mocked** in `src/lib/payment.ts`: `charge()` only accepts the fixed `TEST_CARDS` numbers (two approved, one declined).
- Shared UI: `Header`, `AuthCard`, `Ticket` in `src/components/`; `cn` helper in `src/lib/utils.ts`; `@/*` maps to `src/*`.
- `src/lib/error-*.ts` and `lovable-error-reporting.ts` are Lovable's error-capture plumbing.
